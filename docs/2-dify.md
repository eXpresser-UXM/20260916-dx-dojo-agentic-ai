# Difyの構築手順

Supabase側の準備（[1-supabase.md](1-supabase.md)）が完了している前提で、Dify上に4つのアプリ（専門家A・専門家B・専門家C・コンシェルジュ）を構築します。専門家3人を先に作ってから、最後にコンシェルジュから専門家への「つなぎこみ」を行う順番がおすすめです（当日のハンズオンでは、専門家A・Bとコンシェルジュを先に組み、専門家Cだけをあとから手動で追加します）。

## 0. 全体構成のおさらい

- **専門家A・B・C**：Difyの「Agent（ベータ版）」アプリとして作成します。それぞれ独立したチャットアプリで、コンシェルジュから`/chat-messages` APIで呼び出されます。
- **コンシェルジュ**：Difyの「チャットフロー」アプリとして作成し、内部にAgentノードを1つ配置します（マルチターンの会話・会話変数を使うため、「ワークフロー」アプリではなく「チャットフロー」を選びます）。専門家A・B・Cはこのノードの「カスタムツール（Custom Tool）」として登録します。
- コンシェルジュ・専門家いずれのアプリも、モデルにはGemini APIキー（無料枠）を使う想定です。無料枠にはレート制限があり、ハンズオン当日に複数人が同時にアクセスすると一時的にエラーが出ることがある点は、参加者にも事前に共有しておくと親切です。

## 1. 専門家B（注文・商品情報スペシャリスト）を構築する

1. Difyで新規アプリ「Agent（ベータ版）」を作成する
2. 「指示（Instructions）」欄に [`dify/expert_b_prompt.md`](../dify/expert_b_prompt.md) の「## 最重要ルール」以降の本文をそのまま貼り付ける
3. ツールとして、Supabase公式プラグインを追加し、[1-supabase.md](1-supabase.md) で作成した**ECサイトDB用Project**のProject URL・API Keyで認証情報を設定する
4. `Get Rows` / `Update Row(s)` をツールとして有効化する
5. アプリを公開し、「APIアクセス」からAPIキーを発行しておく（後でコンシェルジュ側のCustom Toolに設定します）

## 2. 専門家C（配送追跡スペシャリスト）を構築する

手順は専門家Bとほぼ同様です。当日のハンズオンでは、ここをあえて参加者自身の手で完全手動で行う想定です（DSLインポートは使いません）。

1. Difyで新規アプリ「Agent（ベータ版）」を作成する
2. 「指示（Instructions）」欄に [`dify/expert_c_prompt.md`](../dify/expert_c_prompt.md) の本文をそのままコピー＆ペーストする
3. ツールとして、Supabase公式プラグインを追加し、**配送会社DB用Project**（専門家Bとは別Project）のProject URL・API Keyで認証情報を設定する
4. `Get Rows` をツールとして有効化する
5. アプリを公開し、APIキーを発行する

## 3. 専門家A（マニュアル・FAQスペシャリスト）を構築する

専門家Aは、SupabaseではなくDifyの「ファイル」機能でアップロードした3つのドキュメントを直接参照する構成です（RAGの実例として、ナレッジに無いことは答えない設計にしています）。

1. Difyで新規アプリ「Agent（ベータ版）」を作成する
2. 「ファイル」欄に [`knowledge/terms_of_service.md`](../knowledge/terms_of_service.md)・[`knowledge/privacy_policy.md`](../knowledge/privacy_policy.md)・[`knowledge/user_manual.md`](../knowledge/user_manual.md) の3ファイルをアップロードする（Agents（ベータ版）はアップロードしたファイルをシェルサンドボックス内に自動配置し、エージェントが`grep`等で検索・参照できるようにする仕組みのため、追加のツール設定は不要です）
3. 「指示（Instructions）」欄に [`dify/expert_a_prompt.md`](../dify/expert_a_prompt.md) の本文を貼り付ける（プロンプト中のファイルパス表記`.dify_conf/files/...`は実機確認済みですが、環境によって変わる場合はプロンプト側の表記を実際のパスに合わせて調整してください）
4. アプリを公開し、APIキーを発行する

## 4. コンシェルジュを構築し、専門家とつなぎこむ

1. Difyで新規アプリ「Chatflow」を作成する
2. フロー内にAgentノードを1つ配置する
3. Agentノードの「指示（Instructions）」に [`dify/concierge_prompt.md`](../dify/concierge_prompt.md) の「## 役割」以降の本文を貼り付ける
4. Difyの画面上部ナビゲーション「ツール」ページ→「カスタム」タブ→「カスタムツールを作成」から、専門家A・B・Cそれぞれに対応するCustom Toolを3つ作成する。各ツールは、対応するスキーマファイル（[`dify/expert_a_tool_schema.json`](../dify/expert_a_tool_schema.json) / [`dify/expert_b_tool_schema.json`](../dify/expert_b_tool_schema.json) / [`dify/expert_c_tool_schema.json`](../dify/expert_c_tool_schema.json)）をOpenAPIスキーマとしてそのまま貼り付けて作成する
   - **注意：「API拡張（API Extension）」という似た名前の別機能と混同しないこと。** API拡張はDify独自の呼び出し契約に従う専用サーバーを登録するための機能で、一般的なAPIをそのまま登録すると`404 Not Found`になります。ここで使うのはあくまで「ツール」→「カスタム」の、OpenAPI/Swaggerスキーマを貼り付けて作る方のカスタムツールです。
5. 各Custom Toolの認証設定（Authorization、Bearer Token）に、手順1〜3でそれぞれ発行した専門家アプリのAPIキーを設定する
6. 作成した3つのCustom Toolを、コンシェルジュのAgentノードのツールリストに追加する
7. コンシェルジュのアプリを公開し、動作確認する（専門家Cをまだ追加していない段階でも、専門家Cへの言及がなければ問題なく動作します）

### つなぎこみ部分のポイント

- 各Custom Toolのリクエストボディは`response_mode: streaming`固定です。専門家アプリはいずれも「Agent（ベータ版）」であり、Difyの仕様上`blocking`モードが使えないため、必ず`streaming`を指定します。
- レスポンスはSSE（Server-Sent Events）形式の生テキストで返ります。`event`が`agent_message`または`message`のイベントから`answer`フィールドを順につなげたものが、専門家からの回答本文になります。Difyのカスタムツールの応答パース設定、またはAgentノード側で、この組み立てが行われるように設定してください。
- 各`*_tool_schema.json`の`description`（ツールの説明文）には、そのツールで「何ができて、何ができないか」（例：専門家Aは規約・マニュアルの説明のみで実行系の処理はできない、専門家Bの4つの処理は氏名・生年月日が必要、等）を書き込んであります。コンシェルジュ側のプロンプトはこれらの詳細を知らなくても動くように作られているため、**専門家側の仕様を変更した場合は、まずこのスキーマファイルの`description`を更新してください**（コンシェルジュのプロンプト自体を直す必要は基本的にありません）。

## 5. 動作確認

- 専門家A・Bとコンシェルジュまで組めた時点で：「おすすめの商品を教えて」「注文履歴を見せて」のような問いかけで、本人確認（氏名・生年月日の聞き取り）を含めて一連の流れが動くことを確認します。
- 専門家Cを追加した後：「配送状況を確認して」のような問いかけで、追加したばかりの専門家Cが正しく呼び出されることを確認します。

## 6. 既知の注意点

- Difyの`dify/`配下のファイルを編集しても、Dify側の設定（各アプリの指示欄、Custom Toolのスキーマ）には自動反映されません。プロンプトやスキーマを修正した場合は、該当箇所をDifyの画面上に再度貼り付け直してください。
- `Update Row(s)`（専門家Bのキャンセル・返品処理）は本番前に直接動作確認しておくことを推奨します。詳細は [1-supabase.md](1-supabase.md) の該当セクションを参照してください。
- Gemini APIの無料枠にはレート制限があります。複数アプリ・複数参加者が同時にアクセスする場面では、一時的なエラー（503等）が起こり得ます。
